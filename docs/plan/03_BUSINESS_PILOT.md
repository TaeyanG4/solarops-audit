# SolarOps Audit — 90일 사업 검증·첫 매출 실험 계획

> 사업 가설은 아직 확인되지 않았다. 개발 자료가 있다는 사실은 곧 고객의 구매 의사를 뜻하지 않는다. 이 문서의 수치는 **시장 실측이 아닌 실행 가설**이며, 실제 매출·정확도·절감액으로 소개하지 않는다.

## 1. 고객을 좁게 정의한다

**초기 ICP(Ideal Customer Profile)**
- 여러 발전소 운영 리포트를 정기 작성하는 국내 태양광 O&M 전문업체.
- 관리 발전소 수(가설): 5~50개. '일반 발전소 소유주'보다는 실제 보고서 작성 책임자에게 접근.
- CSV 다운로드/이메일 전송 가능한 기존 모니터링 솔루션을 사용하며 담당자가 수동 취합하는 조직.
- 월간 보고서 발송, 품질 확인, 이슈 대조 과정에서 시간이 소모되는 곳.

**사면 안 되는 고객을 초기부터 필터링**
- 모든 보고/데이터 감사가 기존 솔루션에서 자동화되어 추가 비용을 지불할 이유가 없는 곳.
- 원천 데이터 제공 권한이 없는 곳.
- 현장 제어·법적 성능보증·장애 원인 확정만 원하는 곳(초기 제품 범위 밖).

## 2. 검증할 '불편' 4가지

1. 서로 다른 인버터/데이터 공급자의 CSV 포맷 병합에 걸리는 시간.
2. 한 달 뒤 보고서 수정 요청을 받았을 때 데이터 출처·계산 버전을 재현하기 어려운 문제.
3. 센서 데이터 누락/보간과 실제 발전 저하 의심 현상이 혼동되는 문제.
4. 고객사마다 보고서 형식이 달라 반복 작업이 발생하는 문제.

## 3. 고객 인터뷰 스크립트(약 20분)

- 현재 몇 개 발전소에 대해 누가 월간 보고서를 작성하나요?
- 지난달 실제로 어떤 파일을 어느 시스템에서 내려받았나요? 가능한 범위에서 화면이나 익명 파일을 보여줄 수 있나요?
- 지난 3개월간 누락 데이터·보고서 재작성·점검 우선순위 때문에 추가로 소모한 시간은 얼마나 되나요?
- 현재 쓰는 O&M/모니터링 제품의 가격과 해결되지 않는 문제는 무엇인가요?
- 제가 원본을 보존하며 데이터 완전성·보간율·저출력 검토 구간을 자동 표시하면 어느 업무가 줄어드나요?
- 도입 결재자는 누구이며, 실제 계약을 위해 보안·업로드·운영보고 요건이 있나요?
- 4주 파일럿을 **유료**로 검토한다면 어떤 산출물이 반드시 필요하고, 얼마 이상의 가치가 있어야 하나요?

**금지:** '이런 기능 좋죠?' 같은 유도 질문, 아직 구현되지 않은 성능 보장, 실제 고장 탐지 정확도를 근거 없이 주장하는 발언.

## 4. 제안 상품 가설

| 구분 | 범위 | 시도할 가격 | 위험 |
|---|---|---|---|
| 유료 시험 서비스 | 승인된 CSV, 최대 10개 발전소, 4주, 주간 DQ 요약 + 월간 1회 보고, 수정 1회 | 20만 원 / 4주 | 고객별 포맷 수작업 비용 |
| 월 정기 보고 | 주기적 파일 공급과 데이터 검증, 월간 리포트 + 확인 필요 구간 | 월 15~30만 원 / 조직 | 보고 정확성과 일정 책임 |
| 맞춤 연동 | 다른 제조사 데이터 어댑터 추가 | 별도 구축 견적 | 비용 산정·유지보수 |

위 금액은 가격 실험용 가설이다. 국내 Solarlog 기본형의 100kW당 월 35,000원은 **하드웨어·시공·장기 계약이 포함된 다른 상품**이므로 동등 가격 비교 자료로 사용하지 않는다.

## 5. 가치 계산법과 수익성

- 고객의 시간 절약 효과(가설) = `(기존 월 업무시간 - 도입 후 월 업무시간) × 고객이 인정한 시간당 업무 가치`.
- 잘못된 경고의 비용 = `추가 검토 시간 × 시간당 비용`. 정확하지 않은 알림이 많은 경우 제품 가치가 마이너스가 될 수 있다.
- 공급자 월간 기여이익 = `고객이 지급한 매출 - 고객별 호스팅 - 수동 검수 - 고객지원 - API/저장소 - 결제수수료 등 변동 비용`.
- 목표는 매출뿐 아니라 월간 고객별 수동 작업 시간을 함께 줄이는 것.
- 발전량 증가·발전 손실 회복 금액을 근거 없이 영업 제안에 넣지 않는다.

## 6. 30일 고객 검증 계획

| 기간 | 고객 실험 | 남길 근거 | 실패 시 |
|---|---|---|---|
| D1-D7 | 20곳 조사, 적절한 담당자에게 합법적으로 연락, 3~5건 인터뷰 | 문제·대안·가격 메모 | ICP 더 좁히기 |
| D8-D14 | 인터뷰 누적 10건, 1개 업무로 문제 좁히기 | 반복 pain 3건 이상, 현재 소요시간 | 재가설 설정 |
| D15-D21 | 합성/공개 데이터의 샘플 리포트 시연 + 수동 Concierge 실험 | 사용 후 피드백, 필요한 필드 | 보고서 형식 수정 |
| D22-D30 | 명시적 파일럿 조건·가격 제안, 승인 자료 확인 | 유료 의향/실제 계약·결제 여부 | 무상 연장 대신 장애물 인터뷰 |

**파일럿 시작 조건:** 데이터 소유/제공 권한을 갖춘 담당자 서면 승인, 전송/보관/삭제 규정, 목적 범위 합의, 보고서의 참고용·수작업 검토 필요 조건.

## 7. 90일 의사결정 게이트

- **Gate B1(30일):** 인터뷰 10건 완료 및 공통된 구체 문제 1건 이상 확인. 미통과면 제품 범위 재정의.
- **Gate B2(60일):** 실제 고객 파일 제공 권한 또는 합리적인 연동 경로 확인. 실패면 공개 데이터 데모만 유지하고 수익화 주장을 중지.
- **Gate B3(90일):** 유료 파일럿 계약/실결제 시도 결과와 서비스 제공 원가 보고. 유료 고객이 0명이어도 이유를 문서화하고 가격/고객군을 재조정.

## 8. 고객 데이터 보안 체크리스트

- [ ] 수집 목적·파일 종류·보존 기간·책임자 합의.
- [ ] 고객이 데이터 재사용·수익사업 활용을 허가할 권한 보유.
- [ ] 공개 저장소/개인 클라우드/외부 LLM 프롬프트에 고객 원본 업로드 금지.
- [ ] 테스트용 마스킹·합성 파일과 실제 고객 파일 별도 보관.
- [ ] 계정 권한, 암호화, 백업, 삭제·반출, 유출 사고 연락 절차 합의.
- [ ] 산출물의 '잠정 검토 대상'과 '확정된 설비 고장'을 분리.

## 9. 초기 고객에게 판매할 단 하나의 약속

> '기존 모니터링 솔루션을 대체하지 않고, 귀사가 제공한 데이터를 정해진 날짜에 일관된 규칙으로 검증하여 보고서 작성·재검토 시간을 줄이겠습니다. 분석 근거와 데이터 누락/보간 여부를 함께 제공합니다.'

이는 **제안 문안**이다. 실제로 얼마를 줄이는지는 고객 데이터를 이용한 파일럿 측정 후에만 숫자로 홍보한다.
