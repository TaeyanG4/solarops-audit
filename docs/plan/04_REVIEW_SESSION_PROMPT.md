# 새 독립 세션 검토 요청서 (그대로 복사하여 사용)

**중요:** 기존 구현 세션을 이어서 검토하지 말고 *새 Codex/ChatGPT 세션*을 열고 이 프롬프트와 기획 문서들만 전달한다. 검토자는 코드 작성보다 결함 발견을 우선한다.

```text
당신은 SolarOps Audit 사업·데이터 엔지니어링 기획서의 독립 외부 검토자다.
첨부된 01_MASTER_PRD.md, 02_CODEX_EXECUTION.md, 03_BUSINESS_PILOT.md를
작성자의 설명이나 과거 대화에 의존하지 말고 독립적으로 읽어라.

목표: 실제 1인 개발자가 Windows+WSL2에서 구현해 태양광 O&M 고객에게
유료 파일럿을 제안하는 데 방해가 되는 결함을 찾아라.

다음 항목을 모두 감사하라.
1. 사업성: 특정 ICP/불편/대안/가격/판매 경로, 경쟁 서비스와의 차이, 검증 불가 가정.
2. 데이터: BR-PVGen README 실제 필드 vs 설계, id 타입, 보간/결측, UTC/단위,
   원본 오류와 합성 시나리오 구별, 라이선스와 논문 인용.
3. 아키텍처: WSL2 메모리, Compose와 kind 사이 네트워크·DB 경계,
   Airflow 3 Provider/Helm/LocalExecutor+KPO 호환, 최소 RBAC/Secret, 이미지 태그.
4. 신뢰성: 멱등성, 버전 정책, staging 후 원자적 커밋, 재처리, crash, 동일키 상이값.
5. 보안: 고객 데이터, 개발용 암호, 외부 노출, tenant 분리, zip-slip/zip bomb.
6. 분석: kWh 적분의 한계, 야간 조건, 허위 고장/실제 손실액 주장 방지.
7. 테스트: 검증 가능한 pass/fail 조건과 과장된 범위.
8. 구현 순서: 코덱스가 작업별로 만들 수 있는지, 빠진 종속관계와 과도한 인프라 비용.

출력 형식(한국어):
- [Blocker/High/Medium/Low] 위험도, 문서/절, 문제, 실패 예시, 구체적인 수정 권고
- 문서 내 상충되는 문장과 누락된 인터페이스
- 확인된 사실 vs 확인되지 않은 가정
- 12주 내 구현을 위해 축소할 부분
- 'Codex M0 구현 승인/조건부/보류' 결정과 근거

기획서가 완벽하다고 가정하지 말고 실제 장애 시나리오로 공격하라.
참고 링크가 존재한다고 내용까지 검증된 것처럼 주장하지 말라.
수정이 필요한 경우 원문 전체를 다시 쓰기보다 변경 위치/패치 지침으로 보고하라.
```

## 작성자가 검토 결과를 반영할 때
- 높은 위험도부터 원문 수정 → 대응 위치·사유 기록 → 검증 테스트 업데이트 순서로 반영한다.
- 독립 세션은 실제로 실행되지 않았다면 리뷰 완료로 표시하지 않는다.
- 데이터 품질 및 안전 관련 Blocker가 남으면 유료 파일럿 및 대외 공개를 보류한다.
