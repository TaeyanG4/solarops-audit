# 포트폴리오 산출물 평가 기준 v1

2026-10-23 사용자 요청에 따라 **면접·개인 역량·라이브 코딩·채용 가능성은 평가하지 않습니다.** 코드·실행 증거·문서만 평가합니다. 이전 모의 면접 점수와 직접 비교하지 않습니다. 평가를 반복해도 이 기준을 점수에 맞춰 바꾸지 않습니다.

## 대상과 경계

대상은 공개/합성 태양광 자료의 로컬 배치 데이터 엔지니어링 포트폴리오입니다. BR-PVGen 처리·보고, ONS 증분 수집, SQLite/파일과 PostgreSQL/MinIO, Airflow/KPO, 읽기 API·대시보드, 재현 절차와 주장 근거를 평가합니다. 데이터 무결성·보안·실패 게시·설명 정확성은 범위 안에 포함됩니다.

고객 영업·상용 인증·공개 배포·외부 SLO·다중 호스트 고가용성은 구현 목표가 아닙니다. 미구현 사실과 선택 이유를 명확히 설명해야 합니다. Kafka/Spark 등 특정 도구의 유무를 가점·감점으로 사용하지 않습니다. 범위 밖 기능이 없다는 이유와 범위 안 기능이 불완전하다는 이유를 구별합니다.

## 고정 배점

각 세부 항목은 0~5점입니다. 0=없음/틀림, 1=주장만 있음, 2=부분 구현·주요 공백, 3=구현과 제한된 검사, 4=대표 실행 근거와 명시된 한계, 5=범위에 맞는 재현 가능한 근거·일관된 계약·확인된 미해결 문제 없음. 근거 없는 만점이나 실행하지 않은 검사의 통과를 기록하지 않습니다.

## 독립 평가 절차

1. 검증을 마친 동일 커밋을 Fable(Claude Code)과 Astra의 새 독립 세션에 제공합니다. 실제 모델·커밋·도구·읽은 범위·실행한 검사를 기록합니다.
2. 평가자에게 이전 점수·상대 평가·요구 점수를 전달하지 않습니다. 파일·서비스·데이터는 읽기 전용으로 검토하고, 부작용 없는 작은 검사는 실행 범위를 명시합니다.
3. 총점과 항목별 근거, 발견 문제의 영향·코드 위치·재현 여부, 최소 개선안을 요청합니다. 면접 질문이나 지원자 판단은 요청하지 않습니다.
4. 메인 세션은 지적을 코드와 작은 입력으로 확인합니다. 잘못된 지적은 근거와 함께 보류하고, 확인된 결함은 점수화해 plan에 등록합니다. 평가 원문은 바꾸지 않고 수용 판단을 별도 기록합니다.
5. 의미 있는 코드·문서·실행 증거 개선 뒤에만 재평가합니다. 변화 없는 코드에서 유리한 점수가 나올 때까지 반복하지 않습니다. 기준 변경이 필요하면 이유·새 버전을 먼저 기록하고 이전 점수와 구분합니다.

평가가 높아도 확인된 중요 결함이나 필수 검사 실패가 있으면 완료로 처리하지 않습니다. 평가는 AI의 판단이며 외부 감사·품질 보증을 대체하지 않습니다.
