# 3~5분 시연과 재현 절차

두 경로를 구분합니다. **새 checkout에서는 다운로드 없는 합성 복구 데모**로 재현성을 보여줍니다. 공개 자료가 이미 준비된 이 PC에서는 아래 ONS·BR-PVGen 경로로 실제 원천을 보여줍니다. 합성 데모를 ONS 수집 성공 실적으로 사용하지 않습니다.

## 1. 다운로드 없는 복구 시나리오

Python 3.12와 uv를 준비한 checkout에서:

```text
uv sync --frozen
uv run python scripts/demo/portfolio_demo.py --serve
```

매 실행마다 새 `data/portfolio-<UTC 시각>` 디렉터리를 만듭니다. 출력 경로를 지정하려면 `--output data/my-demo-01`을 사용합니다. 이미 있는 경로는 거부하므로 이전 자료를 덮어쓰지 않습니다. 데모는 환경에 PostgreSQL/S3 설정이 있어도 독립 SQLite·로컬 파일을 사용합니다.

이 명령이 확인하는 것은 다음과 같습니다.

1. 합성 7일 자료 처리 후 활성 파티션의 논리 해시 저장.
2. 다음 실행의 DB 커밋 중간에 의도적으로 실패 주입.
3. 기존 활성 파티션과 해시가 유지되는지 확인.
4. 다시 실행하고 7개 날짜의 논리 해시가 같은지 확인.
5. 보고서와 `evidence.json` 생성 후 [8503 대시보드](http://127.0.0.1:8503/) 열기.

서버 없이 증거만 만들 때는 `--serve`를 생략합니다. GitHub Actions에서도 이 시나리오를 실행하며 합성 보고서와 증거를 아티팩트로 보관합니다.

정확한 격리 경로를 기록하려면 새 이름으로 실행합니다(이미 존재하는 경로는 재사용하지 않습니다).

```text
uv run python scripts/demo/portfolio_demo.py --output artifacts/portfolio-final-demo --serve --port 8503
```

같은 터미널에서 **Ctrl+C**로 종료하면 서버만 멈추고 DB·보고서·증거 파일은 남습니다. Docker, 기존 DB, 공개 원본 다운로드는 필요 없습니다. `uv sync --frozen`은 최초 의존성 준비 시 네트워크가 필요할 수 있습니다.

## 3. 공개 자료가 준비된 환경

| 시간 | 화면 / 근거 | 전달할 핵심 |
|---|---|---|
| 0:00–0:40 | BR-PVGen 전체 현황, 2024-04·공개 | 51개 전체 원천과 월별 5개를 구별. 추정 발전량이며 실측 전력량이 아님 |
| 0:40–1:30 | PS_001 보고서 | 관측 100%와 유효 74.9%가 다른 이유, 무효·누락·원본 보간 구분 |
| 1:30–2:40 | [데이터 출처 → ONS 수집 상태](http://127.0.0.1:8502/?view=sources&source_tab=ons&ons_period=2026-10) | 조회 저장소·마지막 성공·변경 0일을 확인. MWmed와 미명시 시간대는 그대로 보존 |
| 2:40–3:30 | 합성 데모의 실패 실행과 evidence.json | 실패 커밋은 이전 성공 유지, 7일 재처리 해시 일치. 합성 장애 주입이라고 명시 |
| 3:30–4:30 | [공개 DAG 측정](../benchmarks/incremental-v0.5.0.md) | 같은 CLI의 실제 KPO, 직렬36.675→동시2개19.339초와 CPU 증가·단일호스트 한계 |
| 4:30–5:00 | [한 쪽 요약](SUBMISSION.md) | 데이터 계약·원자 게시·재현성이라는 설계 선택, 인증/외부SLO 등 범위 밖 |

ONS 탭의 Compose 기록과 kind 정기 수집은 독립 저장소입니다. 화면은 스케줄러 상태를 확인하지 않습니다. 예정 시간이나 과거 성공만 보고 현재 프로세스가 정상이라고 설명하지 않습니다. ONS가 없는 새 데모에서는 '성공 기록 없음'이 정상입니다.

Compose의 [전체 현황](http://127.0.0.1:8502/?view=overview&period=2024-04&source=public)에서 같은 흐름을 보여줄 수 있습니다. 2024년 4월에 자료가 있는 공개 발전소는 5개이며 전체 데이터셋 51개와 구별합니다.

[PS_001 월간 보고서](http://127.0.0.1:8502/?view=reports&period=2024-04&source=public&plant=PS_001)를 열고 “관측 100%인데 왜 유효값은 74.9%인가?”를 설명합니다. 월 전체 파티션 확보가 모든 전력값의 유효성을 뜻하지 않는다는 실제 예시입니다.

보고서는 메인 본문에서 읽고 일별 내역을 펼친 뒤 CSV·계보 JSON·인쇄용 HTML을 확인합니다. 사이드바의 데이터 품질과 데이터 출처에서 분류/원본으로 이동합니다. 시스템 관리 시연은 [별도8504실행](../runbooks/operator.md#시스템-관리-8504)이 필요하며, 중지 버튼은 실제 서비스에 영향을 주므로 처리 중 작업이 없는 시점에만 사용합니다.
