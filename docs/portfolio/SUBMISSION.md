# SolarOps Audit — 제출용 한 쪽 요약

**공개 태양광 데이터를 검증하고, 갱신·실패·재처리 후에도 숫자의 원본을 설명하는 배치 파이프라인.**

## 문제

관측 슬롯이 100%여도 값이 모두 유효하지는 않습니다. 원본 NULL·보간·누락을 숨기거나, 실패한 작업의 일부 결과를 성공처럼 게시하면 보고서를 신뢰하기 어렵습니다. 갱신되는 원천은 정정·철회·중복과 늦게 완료된 작업까지 처리해야 합니다.

## 설계

- **계약과 출처:** BR-PVGen의 15분 전력에서 추정 kWh를 계산하고 보간·표본 수를 보존합니다. ONS 시간별 MWmed는 원문 시각·검증/예측/미확정 분류를 유지합니다. 시간대가 미명시인 ONS를 임의 UTC 변환하거나 에너지에 합산하지 않습니다.
- **게시 경계:** 원본·산출물을 먼저 불변 객체로 저장하고 검증한 결과만 DB 트랜잭션으로 게시합니다. ONS 월별 성공 cursor와 변경 날짜 manifest는 기대 run ID를 비교해 함께 전환합니다. 실패하면 이전 성공이 남습니다.
- **실행과 조회:** Python 공통 CLI → Airflow 일정/재시도 → Kubernetes 작업 Pod. PostgreSQL은 활성 카탈로그, MinIO는 바이트 저장, FastAPI는 읽기 API와 대시보드를 제공합니다. 서버 없는 재현은 SQLite·로컬 파일로 분리합니다.

## 실행한 결과

| 검증 | 실제 결과와 범위 |
|---|---|
| 공개 역사 자료 | 51개 발전소·인버터 14,400,480행·12,572 일별 파티션. 매 변경마다 전체 재실행한 수치가 아님 |
| 갱신 원천 | kind ONS 9~10월 태양광167,424행·51일, 실제 정기 KPO 성공. Compose 10월69,696행 재확인 변경0일 |
| 제한 병렬 실행 | 동일 공개4일의 일별 task, 직렬36.675→동시2개19.339초(47.3% 단축), 4개 논리hash 동일. 총CPU 24.3% 증가 |
| 실패 복구 | 격리 합성7일에서 커밋 실패 후 이전 게시 보존, 재실행hash 일치, 보고서 생성. 새 checkout CI에서도 실행 |

수집과 성능은 [v0.5.0 측정 조건](../benchmarks/incremental-v0.5.0.md), 최종 화면·재현·CI는 [제출 마감 근거](../benchmarks/portfolio-finish-20261023.md)에 연결합니다. [4~5분 시연](DEMO_GUIDE.md) · [핵심 설계 질문 5개](DESIGN_QUESTIONS.md) · [아키텍처](../architecture/system.md).

## 한계

단일 호스트 kind에서 직렬 후 병렬 각 1회 비교로 캐시·Pod 기동 비용을 포함합니다. 하나의 4일 CLI 배치와 비교한 수치가 아니며 무제한 확장성·고가용성을 보증하지 않습니다. 현장 고장 정답·매출·고객 인증·외부 SLO·다른 물리 호스트 재해복구는 미검증입니다. 저출력은 검토 후보이며 확정 고장/손실이 아닙니다.

**설명 포인트:** 도구 수보다 입력 계약, 커밋 경계, 실패 보존, 결과 동등성, 측정 조건을 코드와 함께 설명합니다. AI 도구 활용 범위는 [스킬 기록](../development/skills.md)에 공개했습니다.
