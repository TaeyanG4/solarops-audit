## v0.4.1에서 처리한 문제

전체 현황의 후속 UI 개선은 [2026-10-23 화면 검증](benchmarks/overview-redesign-20261023.md)에 기록합니다. Agent Browser 1440/768/390px, 접근성·동작·API 응답 비교와 기존 회귀 검사를 수행했습니다. 공통 화면 틀은 갱신했고, 관측 차트와 생성된 보고서 본문의 전면 리디자인은 포함하지 않습니다.

원본 변경/복사 경합과 버전 동시 등록을 차단하고, API 초기화 부작용과 파일 부재·변조 응답을 수정했습니다. 보고서 업로드/DB 실패는 이전 결과를 보존하고 늦게 끝난 오래된 보고서가 최신 포인터를 대체하지 않습니다. 슬롯별 저출력과 연속 검토 사건의 표현도 구분했습니다. [검증·실패 재현](benchmarks/integrity-v0.4.1.md) · [설계 근거](adr/0008-storage-integrity.md).

## v0.4.0에서 처리한 문제

1. 무효 전력만 있는 슬롯을 0 대신 null로 표현하고, 현지 날짜/UTC 경계에서 불필요한 빈 파티션을 만들던 문제를 수정했습니다. DST 누락일 분모와 유효한 0은 유지합니다.
2. 계산 버전을 v2로 분리하고 51개 공개 발전소를 다시 처리했습니다. 12,572개 일별 지표·원본 SHA를 비교했고, 31개 시계열 표본에서 190개의 0→null 수정 외 차이가 없었습니다.
3. 상태를 바꾸지 않는 미완료 실행 진단과 active 연결 조회를 추가했습니다. 시간 경과를 실패 확정으로 해석하지 않습니다.
4. 전용 합성 자료로 SQLite/파일 복원과 같은 서버의 별도 PostgreSQL DB·MinIO 버킷 복원을 검증했습니다. 과거 보고서 API·raw 재처리 해시와 원본 보존을 확인했으며 다른 호스트의 재해복구와 구별합니다.
5. 수익화 판단, 작은 유료 파일럿 범위, 원가 가정과 실측 양식을 기록했습니다. 미측정 값은 0이나 매출 실적으로 채우지 않습니다.

이전 API·출처 필터·패키징·폴더 개편은 [v0.3.1 기록](benchmarks/maintenance-v0.3.1.md)에 보존합니다.

## 다음 우선순위와 완료 기준

| 점수 / 조건 | 남은 일 | 완료 판단 |
|---|---|---|
| 16 / 승인 표본 의존 | 실제 고객 업무·구매 의사와 CSV 매핑 | 이용 권한·단위/시간대/간격 계약, 실제 작업시간·기여이익·입금·재구매 확인 |
| 고객 도입 시 별도 범위 | 인증/권한·HTTPS·감사·모니터링·SLO | 운영 책임과 배포 범위 정의 후 검증; 현재 공개 배포 없음 |

세부 점수와 실행 순서는 루트 [plan.md](../plan.md)가 기준입니다. `2×영향 + 2×정보가치 + 근거확신 + 선행조건해소 + 새접근가치 + (3−비용)`으로 각 요소 0–3점, 최대24점입니다. 동점은 비용이 낮은 일, 정보가치가 높은 일 순입니다. 완료한 항목은 계획에서 제거하고 발견·인계 기록으로 이동합니다.

현재는 로컬 조직별 조회이고 사용자 인증은 없습니다. 일별 사건 경계를 넘는 병합, 자동 알림, 결제, 고객 CSV 업로드도 없습니다. 보고서는 생성 시점 스냅샷이며 후속 적재 후 재생성해야 합니다. JSON 기반 이력의 장기 성능, 대규모 동시 보고서 부하, Pod 확장성은 추가 검증이 필요합니다.
