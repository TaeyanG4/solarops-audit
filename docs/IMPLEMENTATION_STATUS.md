## v0.3.1에서 처리한 문제

1. 잘못된 날짜/역순·동일 기간이 정상 조회로 처리되는 문제와 최댓값 날짜의 서버 오류를 422로 통일했습니다. 발전소 ID 검증도 모든 관련 API에 적용했습니다.
2. 보고서 공개/합성 필터가 발전소 접두사를 추측하던 문제를 실제 출처 계보로 교체했습니다. 기존 보고서는 수정 없이 manifest를 읽습니다.
3. 배포 ZIP의 v0.1.0 고정 이름을 현재 프로젝트 버전으로 바꿨습니다. 전체 입력 목록 검사 후 생성하며 기존 ZIP·민감 파일을 보호합니다.
4. 스크립트 21개를 목적별로 이동하고 호출 경로를 수정했습니다. 오래된 소스 교체 스크립트는 보관하고 실행을 차단했습니다.
5. 상세 실행법을 README에서 분리하고 기술별 선택 이유·대안·한계를 코드/검증에 연결했습니다. 로컬 문서 링크·스크립트 경로·원본 기획 8개 checksum 검사를 CI에 추가했습니다.

## 다음 우선순위와 완료 기준

| 우선순위 | 남은 일 | 완료 판단 |
|---|---|---|
| 1 | 계산 경계 보강: 전력이 모두 무효인 슬롯의 0/null 표현, 비UTC 경계의 누락일 처리 | 경계 fixture로 재현, 계산 버전/기존 결과 호환·재처리 계획 수립 후 공개 자료 전후 비교. 이번 릴리스에서는 계산과 기존 파티션을 바꾸지 않음 |
| 2 | 갑자기 종료된 running/validated 실행 상태 조정 | active 포인터와 실제 작업 생존 여부를 대조하는 dry run, 정상 장시간 작업 오판 방지, 재시도 증거 |
| 3 | 보존·백업·복원 | 기존 증거를 보존한 별도 백업에서 DB와 객체 계보를 함께 복원·검증; 삭제 정책은 사용자 승인 후 적용 |
| 4 | 승인된 고객 스키마 어댑터와 현장 라벨 평가 | 사용 동의·단위/시간대 매핑·익명화 fixture, 검토 후보의 정확도·누락률을 별도 평가 |
| 5 | 외부 서비스 운영 | 인증/권한·HTTPS·감사·모니터링·SLO·운영 책임 정의 후 별도 배포 |

현재는 로컬 조직별 조회이고 사용자 인증은 없습니다. 일별 사건 경계를 넘는 병합, 자동 알림, 결제, 고객 CSV 업로드도 없습니다. 보고서는 생성 시점 스냅샷이며 후속 적재 후 재생성해야 합니다. JSON 기반 이력의 장기 성능, 동시 보고서 생성, 대규모 Pod 확장성은 추가 검증이 필요합니다.
