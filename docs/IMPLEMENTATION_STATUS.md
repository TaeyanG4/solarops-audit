## v0.4.1에서 처리한 문제

현재 화면은 분석/감사 자료/관리로 묶은 사이드바, 공통 선택창, 16/14px 글씨 체계입니다. 월간 보고서의 iframe을 없애고 본문과 인쇄 HTML을 함께 새로 작성했습니다. 독립8504에서 기존 Compose/kind를 제어합니다. [개편 당시 검증](benchmarks/workspace-20261023.md): Python126통과·6제외, Agent Browser107+195명령,1440/768/390px 접근성·동작·API 비교와 실제 전체 중지/복구. [이전 수평 탐색](benchmarks/energy-desk-20261023.md)은 중간안 이력입니다.

원본 변경/복사 경합과 버전 동시 등록을 차단하고, API 초기화 부작용과 파일 부재·변조 응답을 수정했습니다. 보고서 업로드/DB 실패는 이전 결과를 보존하고 늦게 끝난 오래된 보고서가 최신 포인터를 대체하지 않습니다. 슬롯별 저출력과 연속 검토 사건의 표현도 구분했습니다. [검증·실패 재현](benchmarks/integrity-v0.4.1.md) · [설계 근거](adr/0008-storage-integrity.md).

## v0.4.0에서 처리한 문제

1. 무효 전력만 있는 슬롯을 0 대신 null로 표현하고, 현지 날짜/UTC 경계에서 불필요한 빈 파티션을 만들던 문제를 수정했습니다. DST 누락일 분모와 유효한 0은 유지합니다.
2. 계산 버전을 v2로 분리하고 51개 공개 발전소를 다시 처리했습니다. 12,572개 일별 지표·원본 SHA를 비교했고, 31개 시계열 표본에서 190개의 0→null 수정 외 차이가 없었습니다.
3. 상태를 바꾸지 않는 미완료 실행 진단과 active 연결 조회를 추가했습니다. 시간 경과를 실패 확정으로 해석하지 않습니다.
4. 전용 합성 자료로 SQLite/파일 복원과 같은 서버의 별도 PostgreSQL DB·MinIO 버킷 복원을 검증했습니다. 과거 보고서 API·raw 재처리 해시와 원본 보존을 확인했으며 다른 호스트의 재해복구와 구별합니다.
5. 수익화 판단, 작은 유료 파일럿 범위, 원가 가정과 실측 양식을 기록했습니다. 미측정 값은 0이나 매출 실적으로 채우지 않습니다.

이전 API·출처 필터·패키징·폴더 개편은 [v0.3.1 기록](benchmarks/maintenance-v0.3.1.md)에 보존합니다.

최신 후속 개선: 실제 등록/발행 월 안내·보고서 시점/버전·단일 실행 진단을 적용했습니다. PostgreSQL 발전소 조회는 실측 후 인덱스1개를 추가해393→15ms로 개선했습니다. [조건·검사·데이터 보존](worklog/2026-10-23-usability.md).

추가 기술 후속: 보고서의 현재 게시 근거 비교(동일/변경/비교 불가), 선택형 서비스 CI, 별도 PostgreSQL/MinIO 인스턴스 복원, 합성10만 건 동시 부하를 완료했습니다. 정렬 인덱스1개로 동시4 깊은 페이지 p95 6409→679ms, 전후1080요청 오류0입니다. [조건·자원·한계](benchmarks/technical-20261023.md). 당시에는 dashboard만 재배포했고, 이후 v0.4.2에서 Airflow/KPO까지 정렬했습니다. 과거 보고서의 없던 필드는 소급 생성하지 않습니다.

DATA-03(19점)과 PERF-03(14점)은 완료했습니다. 공개4일 실제DAG직렬36.7초/동시2개19.3초·논리hash일치이며 더 큰 병렬화는 추가하지 않았습니다. [조건·CPU/메모리·DB/S3·한계](benchmarks/incremental-v0.5.0.md).
