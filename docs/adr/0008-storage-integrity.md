# 0008 — 보존 원본과 조회·공개 경계

상태: 채택, v0.4.1. 계산은 `energy-interval-v2` 유지.

## 문제와 근거

정상 재처리만으로는 계보와 동시성을 입증할 수 없었다. 합성 입력을 원본 보존 직후 변경하면 결과와 기록된 SHA가 어긋났고, SQLite의 읽기 후 쓰기 방식은 서로 다른 입력을 같은 버전에 허용했다. API 시작과 readiness는 없는 저장소를 생성했다. 추가 검사에서는 원본 복사 중 접근과 보고서 역순 완료도 실패했다.

## 결정

- raw는 같은 파일시스템의 UUID staging에 완전히 복사·fsync·SHA 검증한 뒤 `os.link`로 공개한다. 기존 경로는 덮어쓰지 않는다. 경합에서 이미 완성된 파일이 있으면 SHA를 확인해 재사용한다. 정상/실패 staging은 자동 삭제하지 않는다. 원자적 hard link를 지원하는 NTFS/POSIX 파일시스템이 필요하며 지원하지 않으면 안전하게 실패한다.
- 처리기는 metadata·범위 탐색·정규화를 모두 보존 raw에서 수행한다. source_version은 SQL `INSERT ... ON CONFLICT DO NOTHING`으로 확보한 뒤 기존 fingerprint와 비교한다. PostgreSQL과 SQLite에서 서로 다른 입력의 한쪽만 성공하도록 검증했다.
- 조회 Catalog는 SQLite URI `mode=ro`, PostgreSQL 읽기 전용 transaction을 사용한다. API는 스키마/버킷을 생성하지 않는다. 초기화 책임은 CLI 생산자와 `db-migrate`에 있다. 실제 인증·DB 계정별 최소 권한 정책을 대신하는 기능은 아니다.
- 새 시계열·보고서는 catalog에 저장한 SHA로 조회 바이트를 확인한다. 파일 부재404와 저장소/무결성503을 구분하며 내부 경로나 접속 정보를 응답에 노출하지 않는다. SHA 없는 과거 파일은 계속 조회한다.
- 보고서는 한 번의 catalog snapshot으로 만들고 파일 업로드 완료 후 DB transaction에서 이력과 active 포인터를 공개한다. active 갱신은 스냅샷 조회 시작 시각(`generated_at`, UTC)이 기존보다 같거나 새로운 경우만 허용한다. 여러 호스트에서 시계 동기화가 필요하며 같은 시각이면 마지막 커밋이 선택된다. 현재 값보다 오래된 보고서도 이력으로 보존된다.

## 비용과 한계

SHA 조회 검증은 파일 전체 읽기 비용이 있고 raw의 staging 링크는 디렉터리 항목을 남긴다. 저장소와 catalog 둘 다 변경할 수 있는 관리자의 악의적 변조를 증명하는 전자서명은 아니다. 원본 파일시스템·MinIO 자체는 운영자 쓰기 권한이 있으며 WORM을 구성한 것은 아니다. staging·비활성 결과 정리는 보관 기준과 사용자 승인 후 별도 수행한다.

정상 계산식·사건 임계값·논리 해시 계약을 바꾸지 않아 전체 공개 51개를 다시 적재하지 않는다. 새 원본 캡처·조회·발행 경계는 합성 재현과 실제 서비스 검사, 제한된 공개 replay로 검증한다. [증거](../benchmarks/integrity-v0.4.1.md).
