# 0006 — 월별 조회 모델과 실행 이력

수락, v0.3.0.

기존 발전소 화면은 목록 조회 후 발전소별 snapshot을 순차 조회했습니다. 각 snapshot에는 화면이 사용하지 않는 계보·사건·품질 payload도 포함되어 있었습니다. 실행 이력은 정렬되지 않았고 batch와 일별 실행이 섞였습니다.

월별 overview는 조직·시간대·현재 계산 버전·월 범위를 SQL에서 제한하고, 단일 SELECT로 지표와 필요한 발전소 메타데이터만 읽습니다. source_kind는 같은 입력 배치의 source_objects가 모두 같은 종류라는 수집 계약에 따라 첫 객체에서 조회합니다. 월 범위이므로 Python에서 발전소/날짜별 합계를 계산하는 비용을 제한할 수 있습니다. 비율은 슬롯 합계를 분모로 계산하고, 관측된 파티션이 없는 날짜는 null로 둡니다.

현재 JSON 카탈로그 구조를 유지해 기존 저장소에 파괴적인 마이그레이션을 요구하지 않습니다. 더 큰 규모에서 JSON 필터가 병목이면 실행 날짜·종류·상태의 정규 컬럼과 인덱스를 도입합니다. 로컬 단일 요청 개선 결과만으로 이 변경을 미리 정당화하지 않습니다.

실행은 작업과 파티션 두 수준으로 표시합니다. 새 작업은 시작 시각을 완료 이후에도 보존하고 하위 파티션은 batch_id를 기록합니다. 이전 기록의 빠진 필드는 추측해서 채우지 않으며 “기록 없음”으로 표시합니다. 강제 종료된 프로세스의 생존 여부는 DB 상태만으로 확인할 수 없으므로 상태 조정·heartbeat는 후속 과제입니다.

이 변경은 업무 계산과 논리 해시를 바꾸지 않습니다. 추가한 실행 메타데이터도 해시에 포함되지 않습니다. [검증 조건](../benchmarks/workspace-v0.3.0.md), [회귀 검사](../../tests/test_workspace.py).
