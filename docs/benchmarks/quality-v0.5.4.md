# v0.5.4 오류 진단·운영 경계 검증

2026-10-23 Asia/Seoul. 계산 `energy-interval-v2` 유지. [기계 판독 요약](quality-v0.5.4.json), [실패 재현·명령·판단](../worklog/2026-10-23-quality-r3.md).

## 구현과 실제 검사

- BR의 batch/partition 오류 기록과 ONS 수집 실패 기록의 2차 DB/파일 오류가 원래 예외를 덮던 문제를 수정했습니다. 기존 검사3개가 수정 전 실패했고 수정 후 통과합니다. 정상 게시 오류는 숨기지 않으며 원래 예외를 다시 전달합니다.
- `FAILURE_RECORD_WRITE_FAILED` 경고는 run_id/목적지/안전 원인 코드만 남깁니다. 실패 기록이 불가능하면 running이 남을 수 있으므로 [실행 로그·복구 절차](../runbooks/recovery.md#실패-기록-자체가-실패한-경우)를 대조합니다.
- 입력 종류·값/보간/표본수 필드를 고정 오류 코드로 구별합니다. 원본 값·DSN은 포함하지 않으며 원본 행 번호는 제공하지 않습니다.
- 로컬 **140통과·14제외 / 33.18초**, Ruff check/format76파일 통과. 실제 격리 PostgreSQL16.10 + pinned MinIO **13통과 / 22.95초**. 새 영구 검사 함수나 전용 검증 도구는 추가하지 않고 기존 검사를 확장했습니다.
- 합성7일1,342행의 논리hash가 v0.5.2 이전 기준과 동일합니다. 기존 공개 원본·과거 보고서 재작성 없음.

## 명시한 데이터·성능 경계

새 합성 자료에서 인버터 하나를 제거하면 기대 슬롯1,344→672가 됩니다. BR 범위 보호는 발전소 일자 단위이며 설비 목록의 대체가 아닙니다. [계약](../data-contract.md)에 분모 변화를 함께 비교해야 함을 명시했습니다. unknown을 포함하는 일별 CSV/API의 확인된true 비중과 HTML의 불명 표시는 같은 지표·unknown 수를 다르게 전달합니다. 다운로드 문구에도 함께 읽을 필드를 안내했습니다. v2 계산/논리hash·과거보고서는 유지합니다.

공개 replay는 계획원본과 캡처raw를 각각 확인하므로 범위 scan이 두 번입니다. [한 번의 비용과 재현 코드](../worklog/2026-10-23-bounds-reproduction.md)를 전체 replay 실측과 구별합니다. 범위 계산을 다시 최적화하거나 공개 전체 자료를 재처리하지 않았습니다.

## 고정 MinIO와 배포

MinIO 소스SHA·기반digest는 [v0.5.3 빌드 근거](quality-v0.5.3.md#minio-빌드-입력)를 사용합니다. 기존/고정 이미지 내부 `/usr/local/bin/minio` SHA256은 모두 `fbc76569ea811e9c8602fd9993e9c854d0f543e50696ab12c11cdfc0ff8457b1`입니다. Go캐시 사용 빌드이며 두 호스트의 깨끗한 재빌드 동등성을 의미하지 않습니다.

현재 선언은 `solarops-minio:2025-10-15-pinned`이며 kind 단일 저장소는 Recreate로 두 Pod가 동시에 같은 볼륨에 접근하지 않게 합니다. 이번 앱/MinIO 배포·CI 확인은 진행 중이며 완료 결과를 아래에 추가합니다. Airflow constraints는 버전 고정이며 설치 wheel별 hash 강제는 아닙니다.
