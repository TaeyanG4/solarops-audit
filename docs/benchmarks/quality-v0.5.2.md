# v0.5.2 — 독립 피드백의 경계 수정

2026-10-23 (Asia/Seoul). [이전 평가와 실제 재현](../reviews/2026-10-23-interview.md)의 INT-01/02/03을 수정했습니다. 이후 평가는 [고정 산출물 루브릭](../reviews/portfolio-rubric.md)을 사용하며 면접·개인 역량은 제외합니다.

## 수정과 확인

| 경계 | 수정 | 실제 확인 |
|---|---|---|
| 전체 원본 범위의 시각 | 정규화와 같은 `timestamp_utc` 함수, 2,048행씩 범위 집계 | 기존 테스트 확장 후 수정 전 4실패 → 관련 45통과. 구간 밖 naive/off-grid/파싱 불가 입력 거부, 기존 게시 보존 |
| 관측 없는 보고서 | manifest의 보간율 null, HTML의 “알 수 없음” | DST 전체 누락일 2개에서 수정 전 실패 → 관련 3통과. 실제 관측의 0%·이전 보고서 바이트 보존 |
| ONS 원인 코드 | 도메인 코드 허용 목록·안전한 HTTP/연결/IO fallback | 수정 전 실패 → 기존 조건부 수집 검사 통과. 원인 8종 구분, 민감 메시지 비노출·성공 cursor 유지 |

새 영구 테스트 함수·전용 검증 스크립트는 추가하지 않았습니다. 데이터 무결성과 보고서 의미에 관한 기존 검사 4개를 확장했습니다. 오프라인 전체 검사는 **136통과·14제외**(32.59초), Ruff check/format 통과입니다. 제외는 선택형 인프라와 로컬 symlink 권한이며 통과로 계산하지 않습니다.

## 정상 입력 동등성과 비용

수정 전 `548ce66`에서 만든 합성 7일·1,342행을 새 코드로 다른 SQLite/파일 경로에 처리했습니다. **7개 일별 논리 hash가 전부 동일**합니다. 정상 에너지 계산·누락 분모·보간 집계·논리 hash 계약을 바꾸지 않았고 계산 버전은 `energy-interval-v2`입니다.

기존 공개 PS_001 인버터 파일 **138,848,090바이트** 하나를 읽어 이전 SQL 범위 계산과 새 공통 파서의 범위를 대조했습니다. 세 번씩 순서를 번갈아 실행했고 모든 인버터의 min/max가 같습니다. 새 다운로드·전체 발전소 재처리는 하지 않았습니다.

| 범위 계산만 측정 | 이전 | 이후 |
|---|---:|---:|
| 1회 | 1.016초 | 2.422초 |
| 2회(이후 먼저) | 0.651초 | 2.209초 |
| 3회 | 0.788초 | 2.204초 |
| 중앙값 | 0.788초 | 2.209초 |

이 비용은 전체 원본에서 SQL의 허용적인 timezone 추정을 제거하고 Python의 동일 계약으로 검증하기 위해 발생합니다. 한 파일·한 호스트의 캐시가 있는 범위 계산만 측정했으므로 전체 ingest 속도나 기존 KPO 성능 수치를 갱신한 결과로 해석하지 않습니다. 보존 원본과 인버터별 범위만 유지하며 전체 행을 Python 메모리에 모으지 않습니다.

## 보존과 한계

기존 공개 게시 결과·과거 보고서·원본·실패 증거를 변경하지 않았습니다. 공개 원본에서 문제 시각이 실제 발생했다고 주장하지 않습니다. 보고서의 null 수정은 새 발행부터 적용됩니다. ONS의 과거 ValueError 기록은 그대로 유지합니다.

[기계 판독 결과](quality-v0.5.2.json)에 검사 수·정상 해시 동등성·범위 측정을 보존했습니다. 독립 PostgreSQL/MinIO 기존 서비스 검사는 **13통과**, 시험 컨테이너는 중지 후 보존했습니다. 새 합성 데모도 7일 실패 게시 보존·재처리 해시 일치·보고서 생성을 확인했습니다.
