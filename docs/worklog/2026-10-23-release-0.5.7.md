## 컨테이너 설명과 새 clone 재현 확인

- Docker Desktop의 SolarOps 관련 컨테이너 83개(실행 중은 별개인 `codex-lb` 1개)를 분류했습니다. 실제 시스템은 Compose app-db/minio/dashboard, Compose Airflow 5개(중지), kind 노드 1개이고 나머지는 검증 때 만든 임시 컨테이너입니다. kind 노드의 28.9GB 이름 없는 볼륨에 kind DB·MinIO·ONS 자료가 있어 삭제 금지로 표시했습니다. README에 접이식 "실행 구성 요소와 컨테이너별 역할"을 추가했습니다. 삭제는 하지 않았습니다.
- README 빠른 실행 4줄을 scratchpad의 새 clone(`9612fc3`)에서 그대로 실행했습니다: `uv sync --frozen` 1.8초(공유 패키지 캐시 사용), 데모 3.2초 exit 0, `failed_publish_kept_active_data`·`replay_hashes_identical` 모두 true. Docker를 쓰지 않으므로 컨테이너 삭제와 무관하게 재현됩니다. 새 PC에서는 첫 의존성 다운로드에 네트워크가 필요하며, 공개 원본 전체 처리 결과와 ONS 수집 자료는 데모 범위 밖입니다.
