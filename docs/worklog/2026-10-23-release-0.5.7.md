## Docker 정리

- 사용자 승인으로 필요 없는 이미지·캐시를 정리했습니다. 먼저 Compose Airflow 4개 컨테이너(api·scheduler·dag-processor·init)가 0.5.6/0.4.2 이미지를 참조하고 있어 `up --no-start --no-deps`로 0.5.7에 재생성했습니다(`airflow-db` 볼륨 유지). 이어서 검증용 컨테이너 74개를 `docker rm`(볼륨 미삭제), 옛 SolarOps 이미지 태그 41개를 `docker rmi`, 빌드 캐시를 `docker builder prune -a`로 지웠습니다.
- 전후: 이미지 52개 61.73GB → 11개 8.22GB, 컨테이너 84개 1.52GB → 10개 3.7MB, 빌드 캐시 44.83GB → 0. 볼륨 30개 35.14GB는 그대로이며 그중 고아 검증 볼륨 23개 1.39GB는 데이터라 남겼습니다. 다른 프로젝트 이미지(codex-lb·kaggle)는 건드리지 않았습니다. 목록·전후 용량은 Git 제외 `artifacts/cleanup-20261023/`.
- 정리 후 Compose를 잠시 시작해 `/health` 0.5.7·`/ready`·2024-04 overview 1,477,828.846 kWh를 확인하고 다시 중지했습니다. kind 노드의 `/var` 볼륨(28.9GB)이 그대로 연결되어 있음을 확인했습니다. 옛 버전을 다시 실행하려면 해당 커밋에서 다시 빌드해야 하며 버전별 커밋·이미지 ID는 `docs/releases/`에 남아 있습니다.
- 사용자 추가 승인으로 고아가 된 이름 없는 검증 볼륨 23개(1.39GB, `docker volume ls -f dangling=true`)를 삭제했습니다. kind 노드 `/var` 볼륨과 `solarops-audit_*` 5개, `codex-lb-data`는 연결된 상태로 남아 볼륨은 30개 35.14GB → 7개 33.74GB입니다. 전체 정리 합계는 약 101GB입니다.
