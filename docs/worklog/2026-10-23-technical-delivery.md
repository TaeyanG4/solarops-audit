## TECH-01 · 선택형 서비스 CI (20점)

- 기존 서비스 검사5건을 재사용하는 수동 전용 GitHub workflow를 구현했습니다. 임의 포트·별도 DB/버킷·일회성 로컬 실행기로 일반 CI와 기존 서비스를 분리했습니다.
- [첫 CI](https://github.com/TaeyanG4/solarops-audit/actions/runs/39895412331)는5통과/6.15초, 결과 업로드·자기 컨테이너 중지·runner 자동 등록 해제까지 성공했습니다.
- 현재 권한으로 GitHub 무료 잔여량 확인이 불가해 hosted 실행을 추가하지 않았습니다. WSL stdin 개행 수정과 초기 오프라인 runner 등록 해제를 수행했고 등록 토큰은 커밋하지 않았습니다.
- [운영 방법](../../CONTRIBUTING.md#선택형-서비스-ci). 새 테스트 함수·전체 데이터 다운로드·상시 runner는 추가하지 않았습니다.

## TECH-02 · 보고서 게시 근거 비교 (19점)

- 새 보고서의 요청 범위를 기록하고 조직·기간·발전소·출처·시간대·계산 버전에 따라 동일/변경/비교 불가를 반환하는 읽기 전용 API를 추가했습니다. 생성 시각 안내와 실시간 감시를 구별합니다.
- UI UX Pro Max의 contextual status/색 외 텍스트 지침으로16px 상태 안내를 적용했습니다. 처음 검색은 부적합해 좁혀 재검색했으며 기존 디자인을 유지했습니다. Agent Browser로3너비와 실제 공개/합성 상태를 확인했습니다.
- PS_001 공개 보고서를 새 ID로 발행하고 이전 HTML/manifest·공개 overview 바이트를 보존했습니다. 같은 입력 재처리로 변경 상태가 된 별도 합성 보고서도 확인했습니다.
- 기존 보고서·조직/기간/자료 범위·카탈로그 읽기 전용·게시 실패 검사를 보강했고 관련 **21건 통과**입니다. [실제 이미지와 검수](../portfolio/images/technical-20261023/README.md). 새 회귀 함수·브라우저 스크립트는 없습니다.

## TECH-03 · 별도 인스턴스 복원 (18점)

- 기존 복원 스크립트에 `--isolated-target`을 추가했습니다. 새 PostgreSQL/MinIO 컨테이너로 복원하고 성공/실패 모두 자신이 만든 대상만 중지합니다.
- 첫 시도에서 복원 폴더 생성 누락을 발견해 수정했습니다. 실패 증거를 남기고 새 폴더로 재실행해27객체·7파티션·원본/과거 보고서·API·재처리·원본 비변경을 확인했습니다.
- 복원~API 확인0.953초, 전체6.891초는 같은 물리 호스트의 작은 합성 측정입니다. 호스트 재해복구/RTO/RPO로 주장하지 않습니다. [실행 안내](../runbooks/backup-restore.md).

## TECH-04 · 동시 부하와 정렬 병목 (17점)

- 별도 CPU1개/768MiB의 API·DB에서 합성2.5만/10만 건, 동시1/4/8, 세 조회 조건을 측정했습니다. 사전 조사 기준은 동시4 p95>1.5초 또는 오류입니다.
- 전체 깊은 페이지의 외부 정렬 병목을 확인해 조직/정렬 시각/run_id 표현식 인덱스1개를 추가했습니다. 10만 건 동시4 p95 **6409→679ms**, 전후1080요청 오류0입니다. 동시8은 p95약2초로 한계를 남겼습니다.
- 합성/실제 앱 카탈로그 행 해시가 인덱스 생성 전후 동일합니다. 실제 앱 인덱스2.59MiB·초기화약172ms이며 조회 API에는 DDL을 추가하지 않았습니다.
- [전체 표본 조건·수치·자원·한계](../benchmarks/technical-20261023.md). 일회성 probe는 artifacts에 보존하고 영구 부하/회귀 모음을 추가하지 않았습니다.
