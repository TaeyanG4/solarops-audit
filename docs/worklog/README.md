## 유지 규칙

- `handoff.md`: 100줄 이내, 현재 상태·다음 행동·의존성과 최근 수행 요약 최대 8개. 상세 기록을 링크합니다.
- `plan.md`: 미완료 작업만 점수와 선행조건으로 정렬합니다. 완료 항목은 제거하고 결과는 해당 날짜에 기록합니다.
- 날짜 문서: 수행 영역마다 3~6줄로 목적·변경·검사·증거·한계를 요약합니다. 명령이나 긴 근거는 이미 있는 설계·benchmark 문서에 연결합니다.
- 하루 기록이 커지면 `YYYY-MM-DD-topic.md`로 나누고 날짜 문서에서 연결합니다. 같은 결과를 여러 파일에 복제하지 않습니다.
- 과거 검증을 새로 수행한 검사처럼 표현하지 않습니다. 미실행·제외·외부 의존은 명시합니다.
- 연구 가설, discovery ID, 에이전트 슬롯, 필수 독립 리뷰 상태는 요구하지 않습니다.

기존 `handoff.md`와 `discoveries.md`의 원문은 [이관 전 보관본](archive/README.md)에 있습니다. 당시 상태·ID는 역사적 맥락이며 현재 계획이나 작업 규칙이 아닙니다.

## 작성 예시

```text
## 수행 영역
- 목적: 해결할 사용자 문제.
- 변경: 핵심 변경과 선택 이유.
- 검증: 실제 실행한 검사와 결과, 미실행 범위.
- 근거: 설계·코드·CI·이미지 링크와 다음 의존성.
```
