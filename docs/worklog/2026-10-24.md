## 로컬 실행 환경 정리 (원본 자료만 보존)

- 사용자 요청으로 SolarOps 가 쓰던 공간을 재고(폴더 12GB: `data/` 5.7GB·`artifacts/` 5.4GB·가상환경과 도구 0.8GB / Docker 약 40GB: kind 노드 볼륨 28.9GB·Compose 볼륨 3.9GB·이미지 7.2GB) 범위를 사용자가 고른 뒤 지웠습니다.
- 지운 것: `.tools/kind delete cluster --name solarops`(노드·볼륨·kubeconfig), `docker compose ... --profile "*" down -v --remove-orphans`(컨테이너 8개·볼륨 5개·네트워크), 빈 네트워크 `kind`·`solarops-load-*` 2개, 이미지 `solarops-airflow:0.5.7`·`solarops-worker:0.5.7`·`solarops-minio:2025-10-15-pinned`·`kindest/node:v1.35.0`·`postgres:16.10-bookworm`, 폴더의 `artifacts/`·`.venv`·`.venv-linux`·`.tools`, `data/`의 `service-full`·`staging`·`solarops.db*`·`restore-*`·`service-restore-*`·`portfolio-*`·`linux-native`·`reports`·로그 4개.
- kind 노드 볼륨의 27GB 는 릴리스마다 kind 에 넣은 이미지가 kind 안의 containerd 에 쌓인 것이었습니다(읽기 전용으로 열어 확인). 나머지는 kind 안의 PVC 1.8GB·etcd 0.3GB 입니다.
- 남은 것: `data/raw`·`data/source`(BR-PVGen 원본)·`data/fixtures`(합성 입력 93KB)·코드·문서·`.env`, 폴더 3.2GB. Docker 에는 다른 프로젝트(codex-lb·kaggle-top-solutions) 약 2GB 만 남았습니다. Git 작업 트리 변경 없음.
- 한계: Docker Desktop 디스크 파일 `docker_data.vhdx`는 110GB 그대로입니다. 안을 비워도 파일은 줄지 않으며, 압축은 사용자 결정으로 나중에 합니다(Docker Desktop 종료가 필요해 codex-lb 도 멈춤). 다시 실행하는 방법은 [새 PC 가이드](../guides/new-pc.md) 3~5절입니다.
