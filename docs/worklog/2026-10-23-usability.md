## 요청 문구와 DATA-01 (20점)

- “처리 과정을 확인하다”를 **“처리 과정을 확인하기”**로 수정했습니다. 나머지 화면 제목은 이미 명사형이라 유지했습니다.
- `/api/v1/periods`는 조직·보고 시간대·계산 버전·자료 구분에 맞는 게시 파티션을 월별로 집계합니다. 에너지가 0인 등록 월도 포함합니다. 공개12,572파티션·16개월(2024-03~2025-06), 최초 SQL5회 중앙값108.958ms로 범위 조회 비용을 확인했습니다.
- 전체 현황·발전소·품질·출처의 빈 월에서 실제 등록 월로 이동합니다. 보고서는 기존 reports API의 발행 월을 별도로 안내합니다. 고정된 합성 데모 날짜로 보내던 버튼은 교체했습니다.
- UI UX Pro Max의 `empty state recovery clear action labels --domain ux -n 3`에서 레이블·빈 화면·복구 행동 지침을 적용했습니다. 자동 월 전환 없이 사용자가 목록을 선택하고 이동합니다.

## REPORT-02 (18점)

- 보고서 합계 아래에 생성 기준 시각(자료 조회 시작), 입력 버전, 계산 버전을 표시했습니다. 새 적재·재처리·계산 버전 변경 시 재발행해야 한다고 설명하며 현재 DB와 자동 동기화/비교한다고 주장하지 않습니다.
- 통합 본문과 새 인쇄 템플릿에 적용하고 `solarops report --period 2024-04 --plant PS_001 --source-kind public`으로 대표 공개 보고서만 재발행했습니다. 새 ID `5fd1a0be-9514-4f39-ad76-06f80c157ec5`, 원래 ID `d9a964f0-8846-4785-8989-9d392c7927a3` 보존입니다.
- 재발행 전후 source_manifest_hash가 같고 기존 HTML 바이트도 동일합니다(SHA-256 `34045342033d3df1b4bac99240583c3b09524882759581284045b040afb0d8ab`). 과거 UUID의 인쇄물은 수정하지 않았습니다.

## OPS-07 (18점)

- 기존 `inspect_runs`의 시간·게시·하위 상태 판독을 단일 실행에도 재사용하고 `/api/v1/runs/{UUID}/diagnostics`에 연결했습니다. CLI 기본 미완료 목록 계약은 유지합니다.
- 상세의 **진단 조회하기**에서 현재 게시 개수·미완료 기록 해석을 읽고, 같은 날짜/계산 버전/시간대의 현재 결과가 다른 실행이면 그 실행으로 이동합니다. 실패 코드와 합성 장애 주입 설명은 기존 근거와 함께 표시합니다.
- 진단은 조직 범위 SELECT만 실행하며 PostgreSQL 읽기 전용 트랜잭션·SQLite 읽기 전용 연결을 사용합니다. 경과 시간은 프로세스/Pod 사망의 증거가 아니고 자동 실패 처리·재실행은 없습니다. 게시 개수는 모든 버전·시간대 기준임을 명시했습니다.

## PERF-02 (17점)

- demo 조직 실행25,424건에서 아래6조건을 각각5회 측정했습니다. 개선 판단 기준은 로컬 HTTP 중앙값250ms 초과 또는 단일500ms 초과로 먼저 정했습니다. 동일 호스트·순차 요청·20행 페이지·warm DB이며 동시 사용자 SLO가 아닙니다.
- 발전소 조회는 두 SELECT가 전체 JSON을 읽는 순차 스캔이었습니다. PostgreSQL에 `ix_pipeline_run_org_plant` 하나(조직 + payload.plant_id 표현식, 204,800바이트)를 추가했고 두 쿼리가 인덱스를 사용하는 실행계획을 확인했습니다. SQLite·API 응답 필드·정렬은 유지했습니다.
- 쓰기용 Catalog 초기화가 기존 DB에도 인덱스를 생성하고 조회 전용 API는 DDL을 실행하지 않습니다. 로컬 생성 약103ms, pipeline_run·active_partition_manifest·active_report_manifest의 정렬된 전체 행 해시가 생성 전후 동일했습니다.

| 작업 단위 전체 | 210.046 | 212.795 |
| 실패 작업 | 106.943 | 106.309 |

- 원본 SQL 실행계획·각 표본·응답 바이트는 Git 제외 `artifacts/usability-20261023/run-cost-{before,after}.json`에 있습니다. 전체/깊은 페이지는 여전히 스캔·정렬하며 더 큰 이력·동시 부하는 재측정해야 합니다. 캐시·추가 인덱스·정규 컬럼은 이번에 도입하지 않았습니다.

## 검증과 로컬 반영

- 기존 테스트를 사용하고 조직/출처 범위·0발전량·진단의 읽기 전용/다른 조직404·실패 후 기존 게시 결과 보존만 기존 테스트에 보강했습니다. 관련13개 중 검증 코드가 반환 키를 잘못 참조한1개를 수정해 재확인했고 최종 모두 통과, 추가 Catalog 경계2개도 통과했습니다. 새 테스트 함수/상시 스크립트는 없습니다.
- Agent Browser로 기간 선택→공개 자료 이동, 보고서 발행 월 이동·상단 메타데이터, 합성 실패 진단→현재 완료 실행 이동을 확인했습니다. 1440/768/390px에서 문서 가로 넘침0, 모바일 axe3회 위반0, 페이지 JS오류0입니다. 캡처는 원본 DPR2로 보존하며 실제 기기·다른 브라우저·스크린리더 검증은 아닙니다.
- 공개 2024-04 overview API 전후 바이트 SHA가 같습니다. 새 이미지 `solarops-worker:0.4.1-usability-20261023`로 dashboard만 재생성하고 DB·MinIO·kind 서비스와 원본 데이터는 유지했습니다. `/ready` 및 실제 보고서·진단 API를 확인했습니다.
- 로컬 원본은 `artifacts/usability-20261023/`에 저장했습니다. Ruff·JS 문법·diff 검사, 문서 링크549개·스크립트 참조59개·원본 기획 체크섬8개 검사를 통과했습니다. 최종 CI는 전달 확인에 기록합니다. 전체 공개 재처리·전체 로컬 pytest는 반복하지 않았습니다.
