`id`/`ps_id`는 문자열 `PS_001` 형식입니다. README의 Integer 설명과 다릅니다. 1MW 용량도 실제 존재하므로 양수·유한값을 검증하고 1.7MW 하한을 강제하지 않습니다. `nominal_power_mw × 1000 = kW`입니다.

인버터 필수 필드: `datetime, ps_id, inverter_id, total_active_power_w`. 기상 필수 필드: `datetime, ps_id, poa_irradiance_wm2`. `interpolated_keys_total_active_power_w`, `document_count_total_active_power_w` 및 POA의 대응 필드를 확인했습니다. 다른 온도·DC·무효전력·풍속 등 컬럼도 Parquet `raw_json`에 원값을 모두 보존합니다. 미지 컬럼은 삭제하지 않습니다.

PK는 조직/발전소/인버터/UTC 시각입니다. 기상은 조직/발전소/UTC 시각입니다. 타임존 없는 시각, 15분 그리드 밖의 시각, 파싱 불가값, 동일키 상이값은 검증 실패로 기록합니다. 동일키 동일값은 1건으로 계산합니다.

v0.5.2부터 인버터의 전체 관측 범위도 정규화와 같은 UTC 파서를 사용합니다. 요청 기간 밖이라도 분모에 기여하는 행의 시각이 잘못되면 게시 전에 거부합니다. 범위 계산은 2,048행씩 읽고 인버터별 min/max만 유지합니다. SQL의 시간대 없는 시각을 UTC로 추정하는 동작에 의존하지 않습니다.

v0.4.2부터 인버터 ID는 `0` 또는 선행0 없는 양의 십진 숫자이며 int64 범위여야 합니다. `01`, `+1`, 공백, 소수 표현은 범위 계산과 정규화 양쪽에서 거부합니다. 서로 다른 문자열을 한 ID로 조용히 합쳐 품질 분모가 작아지는 것을 방지합니다. 정상 입력의 계산식·v2 논리 해시는 유지합니다.

음수/NULL/무한 전력은 원본을 보존하고 발전량 계산에서 제외합니다. 보간 표시가 NULL이면 '미보간'으로 간주하지 않습니다. 샘플 수가 0/불명인 값이나 필수 측정값이 보간인 슬롯에서는 성능 판단을 하지 않습니다.

원본 CSV는 이미 15분 집계·부분 보간된 자료입니다. 원본 파일에 NULL을 가진 행이 다수 있으므로 **관측 슬롯 완전성**과 **유효값 완전성**을 따로 표시합니다. 분모는 각 인버터의 전체 원본 min/max 관측 범위와 요청 날짜의 교집합입니다. 이것은 실제 설비 가동기간을 독립적으로 확인한 결과가 아닙니다.

발전량은 유효한 15분 관측 슬롯별 `W / 1000 × 0.25` 합입니다. 연결된 두 시각 사이를 보간/외삽하지 않고 각 행을 15분 평균 전력의 근사로 해석합니다. 마지막 관측 슬롯도 0.25h로 계산합니다. 이는 기획서의 2.0kWh golden fixture를 만족하는 명시적 해석이며, 계량 전력량과 일치한다고 보장하지 않습니다.

이상 후보는 POA≥400, AC 출력/설비용량<0.10이 신뢰 가능한 3개 연속 슬롯에서 성립할 때만 생성합니다. 일별 파티션 경계를 넘는 사건 병합은 하지 않습니다. 임계값은 엔진 함수 인수로 변경 가능하며 manifest에 보존합니다. 변경 시 계산 버전을 올려야 합니다.

`energy-interval-v2`에서 논리 해시는 자연키 정렬 후 정규화 측정값·원본 필드·일별 지표·규칙과 파생 품질·후보·시계열로 계산합니다. run_id와 처리시각은 제외합니다. 각 보고서에는 출처/데이터 버전/규칙/생성시각/표시 시간대/활성 파티션 계보가 포함됩니다.

v2는 유효 전력이 하나도 없는 슬롯을 null로 표시하고 실제 유효한 0과 구분합니다. 일부 인버터만 유효하면 그 유효값의 합이며 품질 정보도 함께 확인해야 합니다. 현지 날짜의 UTC 범위와 원본 범위가 겹치는 날만 공개해 비UTC 경계에서 분모가 0인 불필요한 빈 날짜를 막습니다. 범위 내부의 전체 누락일은 계속 공개하며 DST 23/25시간 분모도 유지합니다. 에너지 산식은 그대로입니다. [버전 전환 결정](adr/0007-calculation-v2.md).

새 월간 보고서는 관측 수가 0일 때 원본 보간율을 `null`/“알 수 없음”으로 유지합니다. 관측된 값의 보간 플래그가 명시적으로 False인 실제 0%와 구분합니다. 이미 발행된 보고서는 당시 불변 산출물로 보존하며 수정한 의미는 새로 생성하는 보고서부터 적용합니다.

슬롯 시계열의 `assessment=review_candidate`는 해당 슬롯의 신뢰 가능한 저출력을 뜻합니다. 사건 목록과 `review_candidate_count`는 **3개 연속 슬롯**을 충족한 사건만 셉니다. 화면은 단일 저출력 슬롯과 사건을 구분하며 어느 쪽도 고장 확정이 아닙니다.

v0.4.1은 입력 경로를 직접 재독하지 않고 SHA가 확인된 raw 스냅샷을 처리합니다. metadata의 중복 헤더·행 폭 불일치는 계약 오류입니다. 새 시계열의 `series_sha256`, 보고서 catalog의 `artifact_sha256`은 다운로드 바이트 검증용이며 계산 v2 논리 해시와 별개입니다. 기존 파일을 수정하거나 기존 계보에 해시를 소급 작성하지 않습니다. [저장·동시성 계약](adr/0008-storage-integrity.md).

v0.5.3은 시각 문자열을 `YYYY-MM-DD[T 또는 공백]HH:MM:SS[.소수 1~6자리](Z 또는 ±HH:MM)`로 제한합니다. Python만 받아들이는 compact/week date·임의 구분자와 버려지는7자리 이상 소수초를 거부하며, SQL 파싱 불가행을 먼저 검증합니다. UTC 변환 뒤15분 그리드 조건도 그대로 적용합니다.

BR 입력 버전은 선택 기간의 upsert이며 전체 철회 snapshot이 아닙니다. 요청 날짜의 기존 active가 새 전체 인버터 관측 범위 밖으로 빠지면 첫 날짜 게시 전에 `SOURCE_RANGE_SHRINK`로 거부합니다. 원본 누락/잘림을 조사하고 올바른 완전 원본·새 source_version을 제공하거나, 의도한 지원 구간만 요청합니다. 요청 밖 날짜와 과거 산출물은 보존합니다. BR 날짜 철회는 현재 지원하지 않으며 ONS는 별도 snapshot 계약으로 지원합니다.

보간 true 비중의 분모는 전체 관측 수입니다. v0.5.3 보고서/화면은 모두 불명일 때 “알 수 없음”, 일부 불명일 때 “확인된 비중 · 불명 N슬롯”, 명시 False일 때0%로 표시합니다. 새 manifest의 `observed_slots`·`interpolation_unknown_slots`와 일별 unknown 수를 함께 보존합니다. 기존 v2 지표/논리hash와 과거 보고서는 바꾸지 않습니다.
